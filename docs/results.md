# 결과 (2차)

빈피킹용 소형 체결부품 인스턴스 분할. 학습 **26회**, 전 과정 실측은 `experiments.md`.
기획과 판단 근거는 `proposal.html`. 1차는 `v1/`(데이터셋이 완전히 교체돼 **수치는 인용 불가**).

**한 줄** — 줄여서 만든 소형 객체 곡선은 진짜 소형 객체 성능의 **낙관적 상한**이다.
수준을 5.9배 과대평가할 뿐 아니라 **어떤 처방을 쓸지에 대한 판단까지 뒤집는다** —
P2 헤드가 그 사례다(2-1). 격차는 헤드 구조로도 모델 크기로도 메워지지 않았다.

---

## 0. 무엇을 재려 했나

로봇이 상자에서 나사·볼트·너트·와셔를 집으려면 겹쳐 쌓인 더미에서 개체 경계를 픽셀 단위로
갈라내야 한다. 그런데 공개 데이터의 부품 사진은 거의 전부 근접 촬영이다
(`data/rejected/MANIFEST.md`: **부품이 주인공이면 반드시 근접 촬영이고, 부품이 작게 찍혔으면
반드시 다른 것이 주인공이다**). 그래서 이 분야는 보통 **사진을 줄여** 소형 객체를 만든다.

이 프로젝트의 물음은 그 방법이 타당한가다. 답을 내려면 **줄이지 않은 진짜 소형 객체**가
필요했고, 채택한 데이터 안에서 찾았다 — `rf-arg-fixings3` 의 640×480 그룹
(로봇 작업셀 원거리 장면, 물체 중앙값 **11.6px**, 98.3% 가 32px 미만).
이것이 **대조군**이고 학습에 한 번도 넣지 않았다.

## 1. 핵심 결과

### 1-1 줄여 만든 곡선은 진짜 소형 객체를 과대평가한다

imgsz 640, YOLO11s, 같은 사진(test 217장)에서:

| | box mAP50-95 | mask mAP50-95 |
|---|---|---|
| test (줄여서 작아진 물체 포함) | **0.8136** | **0.6126** |
| **대조군** (원래 작게 찍힌 물체) | **0.1390** | 잴 수 없음* |

**5.9배 차이.** 320·160 으로 내려가면 격차는 15~200배로 벌어진다.

\* 대조군 24장 중 **모든 인스턴스에 사람이 그린 마스크가 있는 사진이 0장**이라 mask AP 를 낼
표본이 안 된다. 그래서 대조군은 box AP 로 재고 SAM 채움본 성적을 참고로 병기한다(D14).

**단, 0.139 를 단독 인용하면 안 된다.** 대조군의 정답 박스가 SAM 이 잡은 물체보다 면적
1.5배로 헐겁다(IoU 0.669). 참고 라벨로 재면 0.1616 이다. **참값은 0.139~0.162 구간**이며,
어느 쪽이든 test 의 1/5~1/6 이다.

### 1-2 무너지는 문턱은 12픽셀 부근이다

대조군 472개, YOLO11s @640, conf 0.25 / IoU 0.5:

| 물체 크기 | 정답 | 찾음 | 검출률 |
|---|---|---|---|
| 24px 이상 | 57 | 52 | **91%** |
| 16–24px | 44 | 27 | 61% |
| 12–16px | 114 | 75 | 66% |
| 10–12px | 72 | 35 | 49% |
| 8–10px | 74 | 23 | 31% |
| **8px 미만** | 111 | 13 | **12%** |
| 전체 | 472 | 225 | 48% |

12px 위로는 60~91%, 아래로는 급락한다. 대조군 중앙값이 11.6px 이라 **절반이 문턱 아래**다.

**단, 이것은 크기 축만 본 것이다.** 같은 크기 구간에서 test 와 대조군을 나란히 놓으면
16-24px 에서 95% 대 59% 로 갈린다 — **크기 외의 도메인 요인이 30%p 안팎을 더 깎는다.**
8절에서 갈랐다.

클래스별 검출률 — bolt 71% / nut 42% / washer 31% / **screw 20%**.
가늘고 긴 나사가 원거리에서 사실상 안 잡힌다(대조군 AP 0.005~0.067, 어느 조건에서도 0.07 미만).

### 1-3 마스크가 박스보다 먼저 무너진다

같은 사진에서 잰 mask/box 비:

| imgsz | box | mask | mask/box |
|---|---|---|---|
| 640 | 0.8136 | 0.6126 | **0.75** |
| 320 | 0.6537 | 0.3429 | 0.52 |
| 160 | 0.4088 | 0.1215 | **0.30** |

(세 줄 모두 YOLO11s · 100 epoch · batch 16 이다. 전에는 640 만 64 epoch 런을 써
비율이 0.81 로 적혀 있었는데, **학습량이 섞인 비교였다** — 맞추니 방향은 그대로다.)

물체가 작아질수록 마스크가 먼저 무너진다. `yolo11-seg` 의 가장 촘촘한 헤드가 stride 8 이고
마스크는 그 1/4 해상도라, imgsz 160 에서 3~14px 물체의 마스크는 격자보다 작아진다.

## 2. 시도한 처방과 결과

### 2-1 P2(stride 4) 헤드 — 대리 지표는 채택하라 하고, 대조군은 하지 말라 한다

설치본의 p2 설정은 전부 탐지 전용이라 **분할용 yaml 을 직접 만들었다**
(`configs/yolo11s-seg-p2.yaml`). 그리고 ultralytics 검증기가 "마스크 원형은 항상 imgsz/4" 를
상수로 박아둬 P2 에서 죽는 것을 고쳐야 했다(`sodseg/p2_seg.py`).

P2 를 붙이면 원형 해상도가 함께 올라가므로 **2×2 로 짜야 원인이 갈린다.**

**세 해상도를 100 epoch 로 맞춰 다시 쟀다(E15).** 처음 표는 P2 쪽이 160·320 에서 각각
+17 epoch 더 돌아 있어 **학습량과 구조가 섞여 있었다** — 규칙 5를 우리 결론에 안 쓴 것이라,
1.57시간을 들여 `s·160`(83→100) · `s·320`(78→100) · `s+P2·320`(95→100)을 다시 돌렸다.

| imgsz | | test box | 대조군 box50 | 교차 box50-95 |
|---|---|---|---|---|
| 160 | 기본 헤드 | 0.4088 | 0.0092 | 0.4550 |
| 160 | **P2** | **0.4820** (+17.9%) | 0.0327 | 0.5085 |
| 320 | 기본 헤드 | 0.6537 | **0.1638** | **0.6731** |
| 320 | **P2** | **0.6798** (+4.0%) | 0.1423 (**−13.1%**) | 0.6142 (−8.8%) |
| 640 | 기본 헤드 | **0.8136** | **0.3769** | **0.5525** |
| 640 | **P2** | 0.7893 (**−3.0%**) | 0.3199 (**−15.1%**) | 0.4775 (−13.6%) |

- **박스 이득은 살아남았다, 다만 320 은 절반으로 깎였다** — +9.1% 였던 것이 **+4.0%** 다.
  160 은 교란이 아예 없었다(83ep 0.4087 → 100ep 0.4088). **같은 +17 epoch 인데 160 에서는
  0 이고 320 에서는 컸다** — 학습량 효과를 한 해상도에서 재 다른 해상도에 옮기면 안 된다.
- **그런데 대조군은 320·640 에서 P2 가 진다.** 320 이 이 프로젝트의 논지를 그대로 재현한다 —
  **같은 두 런에서 줄여 만든 test 는 P2 를 채택하라 하고(+4.0%), 진짜 소형인 대조군은
  하지 말라 한다(−13.1%).** 대조군 없이 다운스케일 곡선만 봤으면 P2 를 채택했을 것이다.
- **160 의 "+255%" 는 성능이 아니다** — 0.0092 대 0.0327 로 둘 다 바닥이다. 대조군 중앙값
  11.6px 가 12px 문턱 아래라 애초에 이길 자리가 아니고, 커 보이는 것은 분모 탓이다.
- **클래스별로는 균일하지 않다. screw 만 P2 에서 오른다** — 대조군 box50 이 320 에서
  0.0032 → 0.0066, 640 에서 0.0183 → 0.0334 다. 하락은 washer 가 끌고 있다(320 −62%).
  절대값이 낮아 처방을 세울 값은 아니지만 **가늘고 긴 물체 쪽 단서로는 남긴다**(6절).

**마스크 쪽 결론은 그대로다** — P2 와 마스크 해상도 2배는 **같은 병목의 대체재**다.
320 test mask50-95 에서 각각 +19.9% / +19.6% 인데 **같이 켜면 내려간다**(0.3754). 둘 중 하나만 켠다.
그리고 epoch 를 맞추고 보니 **320 대조군을 올린 구조 처방은 P2 가 아니라 마스크 해상도였다** —
mr2 는 88 epoch 로 기준선(100 epoch)보다 **적게 돌고도** box50 0.1665 > 0.1638 이다.
학습량 교란이 불리한 방향인데 이겼으므로 방향 논증이 성립한다.

비용: 파라미터 +1.6%, 학습 시간 320 에서 +36%.

**그래서 P2 는 "안 통한 처방" 한 줄이 아니라 논지를 증명한 사례다.** 대리 지표와 실물이
절대 수준만 다른 게 아니라 **처방의 순위까지 뒤집는다**는 것을 같은 런 쌍 안에서 보여준다.
반대 사례가 화질 열화 증강(2-3)이다 — 그쪽은 test·대조군·교차 도메인이 전부 같은 방향이었다.
한계는 seed 하나, 대조군 8장이다. 다만 **두 해상도 × 두 축에서 모두 같은 방향**이라
잡음으로 보기는 어렵다.

**결합(s + P2 + 열화증강) 3회의 결과.** `scripts/run_combo.sh` 로 지금까지 효과가 있던 축을
전부 겹쳤다 — s 크기 + P2 헤드 + 열화 증강(마스크 해상도 2배는 P2 와 같은 병목이라 제외, D20).
320 정본은 배치를 맞춰 `scripts/run_combo_b16.sh` 로 재실행했고, 평가는 `scripts/run_eval_combo.sh`
로 통일 잣대에 맞춰 냈다.

- **640 결합도 이득이 쌓이지 않는다 — 판정 끝났다(E13).** batch 16 으로 재실행해
  (`scripts/run_combo_640_b16.sh`, 100 epoch 완주, 3.0시간) **세 런이 전부 batch 16 ·
  100 epoch** 가 됐다. 배치도 학습량도 같아 320 처럼 방향 논증으로 우회할 필요가 없는,
  **결합 실험에서 가장 깨끗한 비교**다.

  | 640 · batch 16 · 100ep | 대조군 box50 | 대조군 50-95 | 교차 mask50 |
  |---|---|---|---|
  | 기준선 `s` | 0.3769 | 0.1390 | 0.736 |
  | **`s`+열화** | **0.4181** | **0.1480** | **0.897** |
  | 결합(`s`+P2+열화) | **0.3299** | 0.1059 | 0.885 |

  기준선 대비 **−12.5%**, 열화 단독 대비 **−21.1%**. 클래스별로도 전면 하락이라
  한 클래스가 만든 값이 아니다(bolt 0.285→0.252 · nut 0.081→0.033 · screw 0.067→0.051 ·
  washer 0.158→0.088).
- **"batch 8 이라 불리했을 것"이라는 가정은 틀렸다.** 앞서 여기에 "불리한 조건을 받은 쪽이
  진 것이라 결합 탓으로 돌릴 수 없다"고 적었는데, 배치를 맞추자 **더 낮아졌다**(0.355 →
  0.330). 판정 불가는 판정 불가로만 두고 방향까지 추정하면 안 된다는 사례다.
- ~~640 에는 P2 단독 런이 없다~~ **채웠다(E14). 그리고 "320 에서는 P2 단독이 기준선보다
  높았다"는 뒤집혔다(E15).** 여기 적혀 있던 근거는 `s+P2` 0.137(95ep) > `s` 0.129(78ep)
  였는데, **둘 다 100 epoch 로 맞추면 기준선 0.1638 > P2 0.1423 이다.** 320 과 640 이
  같은 방향을 가리킨다 — **P2 는 결합에서만 나쁜 것이 아니라 대조군에서 그냥 나쁘다.**
- **320 결합은 대조군에서 이득이 쌓이지 않는다** — 신뢰할 수 있는 음성 결과이고, epoch 를
  맞추니 폭이 더 커졌다. 대조군 box50: `s` **0.1638**(100ep) → `s+P2` **0.1423**(100ep)
  → **결합 0.116**(100ep). 셋이 전부 100 epoch 라 방향 논증이 필요 없어졌다 —
  기준선 대비 **−29%** 다(전에는 0.129 를 기준선으로 써 −10% 로 적혀 있었다).
- **320 결합의 test mask50-95 이득은 이제 학습량과 갈린다(E15 덕분).** 전에는 0.320(78ep)
  → 0.383(95ep) → 0.406(100ep) 이라 학습량이 섞여 "올랐다"까지만 말했는데, 320 기준선을
  100 epoch 로 다시 돌려 **학습량 효과 자체를 쟀다** — 78ep 0.3196 → 100ep **0.3429**
  (+22 epoch 에 **+7.3%**). 100 epoch 로 맞춘 세 값은 **0.3429 → 0.3749 → 0.406** 이고,
  기준선 대비 **+18.4%** 는 학습량 효과 +7.3% 보다 크다. **test 안에서는 결합이 마스크를
  올린다고 말할 수 있다.** 대조군으로 안 넘어오는 것이 문제이지 test 상승 자체는 실재한다.
- **교차 mask50 이득도 epoch 를 맞추니 줄었다.** 전에는 0.753(78ep) → 0.736(95ep) →
  0.811(100ep) 이라 적었는데, 100 epoch 기준으로는 **기준선 0.794 → P2 0.757 → 결합 0.811**
  이다. 기준선 대비 **+2.1%** 로, 전에 읽던 +7.7% 보다 훨씬 작다. 다만 P2 단독(0.757)보다
  결합(0.811)이 **+7.1%** 인 것은 남는다 — 열화 증강이 원래 교차 도메인을 지키는 축이라는
  점(2-3, D22)에 비추면 **열화 성분이 결합 안에서도 살아 있다는 확인**으로는 읽을 수 있다.
  **"결합 덕분"까지는 여전히 말하지 않는다.**

### 2-2 모델 크기 — 키운다고 되지 않는다

| 모델 | 파라미터 | test box | test mask | 대조군 |
|---|---|---|---|---|
| YOLO11 n | 2.9M | 0.7594 | 0.5766 | 0.1014 |
| **YOLO11 s** | 10.1M | **0.8136** | **0.6126** | **0.1390** |
| YOLO11 m | 22.4M | 0.8031 | 0.5976 | 0.1276 |

n → s 는 오르고 **s → m 은 개선이 없다.** (m 은 77 epoch 에서 조기 종료해 epoch 가 다르므로
"m 이 나쁘다"가 아니라 "키워도 개선이 없다"까지만 말한다.)

### 2-3 화질 열화 증강 — 통했지만 이유가 달랐다

기획서는 "줄인 사진은 실제보다 깨끗하니 노이즈·흐림·압축으로 되돌린다"를 근거로 삼았다.
**물체 크기를 12px 로 맞춰 재보니 그 전제는 성립하지 않았다** — 노이즈는 축소본이 오히려
더 크고(4.49 vs 3.21), 가장 큰 차이는 **대비**였다(미헬슨 0.588 vs 0.255).

그래도 원안을 버리지 않고 실측이 가리킨 처방(`flat`, 대비 축소)과 **함께** 돌렸다.

| 조건 (640, 100 epoch) | test box | test mask | 대조군 | 교차 도메인 |
|---|---|---|---|---|
| 기준선 | 0.8136 | 0.6126 | 0.1390 | 0.5525 |
| **`deg` 노이즈·흐림·압축** | 0.8133 | **0.6224** | **0.1480** | **0.7952** |
| `flat` 대비 축소 | 0.7900 | 0.6093 | 0.1325 | 0.6291 |
| `both` | 0.8140 | 0.6087 | 0.1112 | 0.8085 |

- **원안이 이기고 실측에서 나온 처방이 졌다.** `deg` 가 네 자리 모두에서 `flat` 을 앞선다.
  `flat` 도 교차 도메인은 올리지만(0.5525 → 0.6291, +13.9%) `deg` 의 +43.9% 에 견주면
  **3분의 1** 이고, 그 대가로 대조군 −4.7%(0.1390 → 0.1325)와 test box −2.9% 를 내준다.
  <br>**정정(2026-08-10)** — 여기 원래 "`flat` 은 대조군에서 잡음 범위로 오르고 교차 도메인은
  떨어진다"고 적혀 있었다. **방향이 둘 다 반대였다.** E9 의 64ep 기준선(교차 0.7104 / 대조군

## 3. 데이터 쪽에서 나온 것

### 3-1 SAM 은 쓰기 전에 재는 대상으로 먼저 세웠다

정답 마스크가 있는 1,706개에 정답 박스를 프롬프트로 주고 IoU 를 쟀다.
**합친 0.814 를 그대로 읽었으면 방향을 잘못 잡았다** — 출처별로 가르니
`rf-nuts-and-bolts` 0.910 / `rf-screw-nut-bolt` 0.824 / `rf-arg-fixings3` **0.700** 이었다.

낮은 쪽을 파보니 **정밀도 0.97 / 재현율 0.70** 이었다. SAM 이 새는 게 아니라 정답 안쪽에
더 좁게 들어가 있었고, 그 정답은 꼭짓점 9개짜리 거친 폴리곤이었다. **낮은 IoU 는 SAM 이
아니라 정답 탓**이었고 겹쳐 그린 그림으로 확인했다.

→ 채우기로 결정. **학습용에만** 2,536개(97.3% 통과), 시험지와 대조군은 손대지 않았다.
와셔는 정답이 100% 구멍을 메운 원판이라 SAM 의 도넛을 메워 관례를 맞췄다(IoU 0.834 → 0.903).

### 3-2 정답 품질이 점수의 상한을 정한다

사람이 그린 마스크의 꼭짓점 수 중앙값 — `rf-arg-fixings3` **9** / `rf-nuts-and-bolts` 14 /
`rf-fasteners` 29~93 / `rf-screw-nut-bolt` 화소 단위.

그 결과 640 에서 출처별 mask AP 가 **0.038 ~ 0.775** 로 벌어진다.
합산 0.61 은 **어느 것도 대표하지 않는다.** 소스별 병기가 필수다.

### 3-3 데이터를 골라 붙이는 과정에서 걸린 것들

- **`rf-screw-nut-bolt` 는 종횡비가 왜곡돼 있었다** — 너트 가로세로비 0.59(원형이면 1.0).
  Roboflow 의 `Stretch to 512×512` 흔적. 512×288 로 복원해 1.06 을 확인하고 학습에 넣었다.
- **분할은 촬영 세션 단위로 잘랐다.** 무작위로 나누면 1~2초 간격 연속 프레임이 학습과 평가로
  갈려 실력이 아니라 기억력을 재게 된다.
- **주석 0개 사진은 지우지 않았다.** 공구만 있는 배경 사진이라 오탐을 줄이는 재료다.

## 6. 남은 것

- **`screw` 는 대조군에서 어느 조건에서도 AP 0.07 을 못 넘는다.** 320 에서 P2+열화 결합은

  전이 쪽으로 좁힌 것이다. 가늘고 긴 물체 전용 처방은 여전히 필요하다.
- ~~640 결합 판정 보류~~ ~~640 에 P2 단독 런이 없다~~ ~~P2 이득의 epoch 를 맞춰야 한다~~
  **셋 다 끝났다(E13·E14·E15).** 결합은 이득이 안 쌓이고, 원인은 결합이 아니라 P2 자체이며,
  epoch 를 맞추자 P2 의 박스 이득은 320 에서 절반으로 깎이고 대조군에서는 부호가 뒤집혔다.

### 8-1 읽는 법

**(1) 박스 찾기는 16px 이상에서 안정적이다** — test 93~95%, 대조군도 24px 이상은 94~100%.

**(2) 12px 미만에서는 test 에서도 무너진다** — 8-12px 구간이 **58%** 다.
학습 데이터와 같은 성격의 사진에서도 절반 남짓만 찾는다.

**(3) 찾아도 마스크가 안 맞는다.** test 기준 마스크 IoU 가 12-16px 에서 **0.254**,
32px+ 에서 0.572 다. 빈피킹은 집을 지점을 정해야 하므로 마스크가 필요한데,
**16px 미만에서는 마스크가 실용 수준이 아니다.**

**(4) 정정 — "12px 문턱"은 절반만 맞았다.** 같은 크기 구간에서도 test 와 대조군이 갈린다:

| 크기 | test | 대조군 | 차이 |
|---|---|---|---|
| 8-12px | 58% | 34% | 24%p |
| 12-16px | 84% | 54% | 30%p |
| 16-24px | 95% | 59% | **36%p** |

크기만이 원인이면 두 값이 같아야 한다. **크기 외에 도메인 요인이 30%p 안팎을 더 깎는다** —
대조군은 공구가 섞이고 대비가 낮고 배경이 어수선하다. 앞서 "문턱은 12px"라고만 적은 것은
**크기 축만 본 것이고, 도메인 축이 비슷한 크기의 몫을 차지한다.**

**(5) 대조군의 마스크 IoU(0.59~0.68)가 test 보다 높은 것은 읽지 않는다.**
대조군의 정답 마스크는 33개(7%)뿐이고 전부 꼭짓점 9개짜리 거친 폴리곤이라
**헐거운 정답이 맞추기 쉬운** 것뿐이다(E2-3).

### 8-2 모델 크기의 효과도 크기 구간에서 갈린다

| 크기 | `n · 640` 대조군 | `s · 640 · 열화` 대조군 |
|---|---|---|
| 0-8px | 14% | 21% |
| 8-12px | 25% | 34% |
| 12-16px | 46% | 54% |
| 전체 | 39% | 46% |

작은 구간일수록 상대 이득이 크지만(14% → 21%), **절대 수준은 여전히 낮다.**

### 8-3 그래서 "소형 부품 탐지를 잘하는가"

- **16px 이상**: 잘한다. 검출률 93~95%, 마스크 IoU 0.48~0.57.
- **12~16px**: 찾기는 84% 하는데 **마스크가 0.254** 라 집을 지점을 정하기 어렵다.
- **12px 미만**: 학습 도메인에서도 58%, 낯선 원거리에서는 34% 다. **못 한다.**

**결론 — 이 모델은 "근접~중거리 체결부품 분할"은 매우 잘하고, "원거리 소형 탐지"는 아직 아니다.**
그리고 그 격차를 만든 것이 크기만이 아니라 **크기와 도메인이 반씩**이라는 것이 이번 측정의 결과다.

## 9. 실행 방법

```
scripts/01_build_dataset.py   전처리 -> data/build/
scripts/02_sam_validate.py    SAM 크기별·출처별 IoU
scripts/03_sam_diag.py        IoU 저하의 원인 분리(정밀도·재현율)
scripts/04_sam_washer.py      와셔 구멍 처리와 SAM 모델 비교
scripts/05_sam_fill.py        관문 통과분만 채우기
scripts/06_to_yolo.py         COCO -> YOLO-seg (이미지 복제 없음)
scripts/07_train.py           학습 (--cfg P2 / --mask-ratio / --degrade / --flatten)
scripts/08_eval.py            평가 (출처별 분리, 통일 잣대)
scripts/09_imgstats.py        사진 전체 화질 통계
scripts/10_quality_gap.py     물체 크기를 맞춘 화질 비교
scripts/11_visualize.py       정답/예측 겹쳐 보기 · 놓친 것 · 조건 비교
scripts/12_size_breakdown.py  크기 구간별 검출률·마스크 IoU (8절)
scripts/run_combo.sh          결합(s+P2+열화) 학습 사다리 — 640, 폐기된 320(b8)
scripts/run_combo_b16.sh      320 결합 정본 재실행 (batch 16)
scripts/run_eval_combo.sh     결합 런 평가 (통일 잣대)
```

환경: `~/venvs/sod` (torch 2.6.0+cu124 / ultralytics 8.4.113 / RTX 4070 12GB).
전 과정 재현: seed 0, deterministic, batch 16 고정 — 단 P2 결합 런 2회(640 결합, 폐기된
320 b8)는 **batch 16 을 시도하지 않고** 8부터 시작하는 사다리로 돌렸다. 320 은 이후
batch 16 으로 재실행했고(정본), 640 은 batch 16 이 들어가는지 **재지 않았다**.
