# 결과 정리 (D10)

D1~D9 실측을 하나로 모은 문서. 각 단계의 상세 수치·중간 과정·버린 시도는
`docs/experiments.md`, 원본 데이터는 `outputs/*.jsonl` 에 있다.

실측 규모: **학습 약 130회, 추론·평가 약 90조합**, 세 공개 벤치마크
(MVTec Screws / NPU-BOLT / PCBsmdComponents), RTX 4070.

---

## 1. 이 프로젝트가 던진 질문과 답

**질문**: 작고 얇은 산업 부품을 공개 벤치마크에서 얼마나 정밀하게 탐지할 수
있고, 어떤 기법이 왜 효과가 있는가.

**답 세 줄**:

1. **"몇 픽셀부터 무너지는가"에 데이터셋 무관한 답은 없다.** 같은 8px 객체에서
   PCBsmd 는 mAP@0.5 0.92 를 유지하고 NPU-BOLT 는 0.17 이다. 붕괴 지점은 픽셀
   크기 단독이 아니라 픽셀 크기 x (배경 복잡도 · 대비 · 클래스당 인스턴스 수)로
   정해진다.
2. **다운스케일로 만든 곡선은 진짜 소형 객체 성능을 과대평가하고, 작아질수록 더
   과대평가한다.** held-out 자연 소형 대조군 대비 82% -> 50%(bolt nut 기준).
   이 격차를 안 재고 다운스케일 결과만 보고하면 "실제로는 안 통할 걸 통한다고
   주장"하게 된다.
3. **문헌에서 검증된 기법이라도 전제가 다른 설정에 그대로 올리면 부호가 뒤집힌다.**
   6개 기법 중 실제로 이득을 준 건 2개뿐이고, 그중 하나는 정확도가 아니라 배포
   효율이다.

## 2. baseline — 스케일별 성능 (val mAP@0.5:0.95)

x축은 명목 배율이 아니라 **네트워크 입력에서 실측한 객체 한 변 중앙값(px)** 이다.
데이터셋마다 원본 해상도가 달라 같은 배율이라도 객체 픽셀 크기가 전혀 다르기
때문이다.

| 데이터셋 | 모델 | imgsz 1024 | 512 | 256 | 128 |
|---|---|---|---|---|---|
| mvtec-screws (112.9/56.5/28.2/14.1px) | yolo11n | 0.918 | 0.884 | 0.776 | **0.242** |
| | yolo11s | 0.923 | 0.904 | 0.861 | **0.316** |
| npu-bolt (81/40.5/20.2/10.1px) | yolo11n | 0.407 | 0.295 | 0.214 | 0.057 |
| | yolo11s | 0.470 | 0.343 | 0.245 | 0.040 |
| pcbsmd (67.3/33.6/16.8/8.4px) | yolo11n | 0.816 | 0.807 | 0.754 | **0.522** |
| | yolo11s | 0.824 | 0.822 | 0.780 | **0.643** |

곡선 그림은 `outputs/d2_ap_curve.png`(위 행 mAP@0.5 / 아래 행 mAP@0.5:0.95).

**COCO 의 small 정의(32px)는 세 데이터셋 어디에서도 변곡점이 아니다.** D1 이
"이 데이터셋들은 small 비율이 0%라 소형 벤치마크가 아니다"라고 판단할 때 쓴
기준은 탐지 난이도와 다른 축이었다.

## 3. 기법별 효과 한눈에

전부 같은 지표(val mAP@0.5:0.95), 같은 분할, 같은 학습 프로토콜에서 잰 값이다.

| 단계 | 기법 | 조합 수 | 평균 효과 | 개선/전체 | 판정 |
|---|---|---|---|---|---|
| D3 | YOLO26 (STAL) | 24 | **-0.012** | 9/24 | 이득 없음 |
| D4 | SAHI 타일링 추론 | 24 | **-0.065** | 1/24 | **해로움** |
| D5 | copy-paste 증강 | 16 | **+0.033** | 11/16 | **효과 있음(조건부)** |
| D6 | INT8 양자화 | 8 | -0.010 | 1/8 | 정확도 대신 크기·속도 |
| D7 | WBF 앙상블 | 12 | +0.000 | 9/12 | 조건부, 비용 4배 |
| D7 | NMS 앙상블 | 12 | -0.005 | 4/12 | 이득 없음 |
| D8 | 불확실성 능동학습 | 24회 | ~0 | - | 판정 불가(해상도 부족) |
| D9 | CAM 집중도 진단 | 24 | - | - | **지표 폐기** |

### 효과가 있었던 것

**D5 copy-paste 증강 — 붕괴 지점에서만.** 평균 +0.033 인데 그 대부분이 가장 작은
스케일에 몰려 있다:

| | imgsz 128 baseline -> 증강 |
|---|---|
| mvtec yolo11n | 0.242 -> 0.373 (**+0.131**) |
| mvtec yolo11s | 0.316 -> 0.544 (**+0.229**) |
| npu-bolt yolo11n | 0.057 -> 0.071 (+0.014) |
| npu-bolt yolo11s | 0.040 -> 0.147 (+0.107) |

**네 조합 전부 최소 스케일에서 개선**된다. 학습셋의 작은 객체 인스턴스 수를
늘리는 기법이므로, 이미 인스턴스가 충분해 포화된 구간에서는 얻을 게 없고
데이터 부족으로 무너지는 지점에서만 값을 한다.

**단, 이 프로젝트가 정한 판단 기준은 통과하지 못했다.** 계획서 3.1절의 기준은
곡선 개선이 아니라 "자연 소형 대조군과의 격차 축소"였고, 그 기준으로는 8개 중
4개 개선으로 방향이 없다.

**D6 INT8 양자화 — 정확도가 아니라 배포 효율.** 크기 **3.7배** 감소(37.8->10.2MB),
속도 **1.2~1.8배** 향상을 정확도 0.04 이내(대개 0.01 이내) 손실로 산다. 속도
이득은 입력이 클수록 크다(imgsz 1024 에서 1.8배, 128 에서 1.2배) — **소형 구간
에서는 INT8 이 기대만큼 빨라지지 않는다.**

### 효과가 없었거나 해로웠던 것

**D4 SAHI — 24개 중 23개에서 나빠졌다.** 손해 폭이 `max(원본 변)/imgsz`(= full-image
경로의 축소 배율)를 그대로 따라간다(1.25배에서 -0.004, 15배에서 -0.139). 원인은
명확하다: SAHI 는 **탐지기가 타일 해상도로 학습돼 있다**고 전제하는데, 이 프로젝트의
방법론은 반대로 **원본을 줄여서** 학습한다. 두 전제가 정면 충돌한다. 부작용으로
탐지 수가 최대 407배, 추론 시간이 최대 97배 늘었다.

이건 SAHI 논문에 대한 반증이 아니다. 원 논문은 원본 해상도로 학습한 탐지기에
타일링을 얹었다. **같은 기법을 다른 전제 위에 올리면 부호가 바뀐다는 실측**이다.

**D3 YOLO26 — 데이터셋마다 방향이 다르다.** mAP@0.5:0.95 평균 차이가 MVTec -0.033 /
NPU-BOLT -0.011 / PCBsmd +0.007 로 일관성이 없다. STAL(Small Target Assignment)이
겨냥한 소형 구간에서 일관된 이득이 없다. **단서**: 두 모델을 YOLO11 용으로 정한
조건에서 같게 돌렸으므로 "YOLO26 이 나쁘다"가 아니라 **"이 프로토콜을 그대로
옮겨서는 이득이 없다"** 가 지지되는 문장이다.

**D7 WBF — 위치 정확도가 무너지는 지점에서 역전.** 9/12 에서 최고 단일 모델을
이기는데, **지는 3개가 전부 최소 스케일이고 세 데이터셋에서 예외가 없다**
(scale>=0.25 에서 평균 +0.010, 9/9 / scale=0.125 에서 평균 -0.027, 0/3).
WBF 는 겹치는 박스의 **좌표를 가중 평균**하므로 구성원들이 비슷하게 잘 위치를
잡는다는 전제 위에 있는데, 최소 스케일에서는 그 전제가 깨진다. 비용은 추론 4배.

NMS 앙상블은 4/12 로 최고 단일보다 못한 경우가 더 많다 — **"합치면 좋아진다"가
아니라 "어떻게 합치느냐가 좌우한다"** 가 맞는 서술이다.

## 4. 이 프로젝트의 핵심 발견 — 다운스케일 곡선은 낙관적 상한이다

계획서 2.2절이 우려한 격차를 실측으로 확인했다. NPU-BOLT 의 자연 발생 소형
객체 14장(121개 인스턴스)을 학습에서 완전히 제외하고 대조군으로 두었다.

양쪽 모두 표본이 충분한 유일한 클래스 `bolt nut` 기준, 대조군 AP / val AP:

| val 객체 중앙값 | 67.3px | 33.6px | 16.8px | 8.4px |
|---|---|---|---|---|
| 비율 | **82%** | 70% | 72% | **50%** |

작아질수록 단조롭게 벌어진다. **다운스케일로 만든 곡선을 "이 모델이 작은 물체에
얼마나 강한가"의 답으로 그대로 쓰면 안 된다.**

**단서 — 앞 두 칸(82% / 70%)은 그대로 읽지 말 것.** NPU-BOLT 는 원본 크기가
제각각이라 imgsz 로 맞출 때 사진마다 리샘플링 방향이 다르다. 대조군은 원본이
작은 사진이 많아 imgsz 1024 에서 14장 중 12장이 **확대**되고(보간으로 흐려짐),
일반 val 은 3.6배 **축소**된다(안티앨리어싱으로 깨끗해짐). imgsz 256 이하는
양쪽 다 100% 축소라 방향이 같으므로 **뒤 두 칸(72% / 50%)의 비교가 가장 깨끗
하다.** 다만 이 아티팩트가 하락 추세의 원인은 아니다 — 원인이라면 확대가 가장
심한 1024 에서 비율이 가장 낮아야 하는데 실제로는 가장 높다. 자세한 내용은
`docs/experiments.md` 의 "읽어낸 것 3 한계" 절.

원인은 저수준 통계 차이로 본다 — 소프트웨어로 축소한 이미지는 안티앨리어싱
때문에 실제로 멀리서 찍힌 소형 객체보다 부자연스럽게 깨끗하다. **D5 의 copy-paste
증강이 이 격차를 못 줄인 것도 같은 이유**로 읽는다: 붙인 객체 역시 원본을 잘라
축소한 것이라 실제 소형 객체의 센서 노이즈·블러가 없다. 가진 데이터에서 오려
붙이는 한 원본에 없는 픽셀 통계는 만들 수 없다.

## 5. 실사용 관점 권고

| 상황 | 권고 |
|---|---|
| 객체가 입력에서 30px 이상 | 기법 추가 불필요. baseline 으로 충분하고 대부분 기법이 이 구간에서 0 근처다 |
| 객체가 15px 안팎 | **copy-paste 증강**이 가장 확실한 이득(+0.13~+0.23). 모델을 키우는 것도 이 구간에서만 값을 한다 |
| 객체가 10px 미만 | 데이터셋 특성이 지배한다. 배경이 단순하면(PCBsmd) 8px 에서도 0.52~0.64 가 나오고, 자연 배경이면 0.04~0.07 이다. **먼저 촬영 거리를 줄일 수 있는지 검토하는 게 어떤 기법보다 효과적이다** |
| 엣지 배포 | **INT8 양자화**. 크기 3.7배, 속도 1.2~1.8배를 0.01 안팎 손실로. 단 작은 입력에서는 속도 이득이 1.2배로 줄어든다 |
| 라벨링 예산 | 전체의 **20~30%면 성능의 90~98%** 에 닿는다(MVTec). 불확실성 기반 능동학습은 이 실험 해상도로는 이득이 확인되지 않았다 |
| 앙상블 | 객체가 크면 WBF 가 +0.01 정도. 추론 4배 비용을 감수할 만큼은 아니다. 소형 구간에서는 오히려 해롭다 |
| SAHI 타일링 | **축소 학습한 모델에는 쓰지 말 것.** 쓰려면 타일로 학습해야 한다 |

## 6. 방법론에서 얻은 교훈

실험 결과만큼 중요한, 다시 하면 처음부터 다르게 할 것들.

**1. mAP@0.5 만 보면 열화를 통째로 놓친다.** PCBsmd 는 mAP@0.5 가 8.4px 까지
0.99->0.92 로 거의 평평한데 같은 런의 mAP@0.5:0.95 는 0.82->0.52 로 36% 떨어진다.
작아질 때 먼저 무너지는 건 "찾았는가"가 아니라 **"얼마나 정확히 감쌌는가"** 다.
D2 중반에 기본 지표를 mAP@0.5:0.95 로 바꿨고, D3 에서 PCBsmd 의 YOLO26 우세가
mAP@0.5 로는 안 보이고 mAP@0.5:0.95 로만 보이면서 그 판단이 값을 했다.

**2. 학습이 조용히 발산한다.** `npu-bolt + s급 + 작은 imgsz` 에서 fp16 오버플로로
손실이 NaN 이 되는데, ultralytics 는 발산해도 계속 돌다가 발산 직전 best.pt 를
남긴다. 결과만 보면 "그냥 성능이 낮은 런"과 구별이 안 된다. D2 에서 이 값을
"작아서 어렵다"의 데이터 포인트로 읽을 뻔했다. 자동 감지 후 `amp=False` 재학습을
넣었고, 이후 YOLO26·copy-paste 데이터셋에서도 같은 조건에서 재현됐다.

**3. 부분 결과로 방향을 선언하지 말 것.** D5(첫 런에서 "의도한 방향"), D6(MVTec
4회로 "작은 객체가 더 손해"), D9(yolo11n 하나로 "배경 반응이 원인") 세 번 다
전체 결과에서 뒤집혔다. 실험 기록에 정정을 남겨 습관으로 굳지 않게 했다.

**4. 지표 자체를 먼저 검증할 것.** D9 의 CAM 집중도는 성능과 상관이 -0.08 인데
정답 박스 면적과는 -0.65 로 얽혀 있었다 — "모델이 객체를 잘 본다"가 아니라
"박스가 작다"를 재고 있었다. 그림만 보고 넘어갔으면 그럴듯한 서사를 쓸 뻔했다.

**5. 재현성 조건을 고정할 것.** `batch=-1`(AutoBatch)이 그때그때 VRAM 여유에 따라
다른 배치를 골라, D8 에서 **완전히 같은 데이터로 mAP 가 0.345 vs 0.282** 로
갈렸다. 그 0.063 이 재려던 전략 차이와 같은 자릿수라 실험 자체가 판정 불가가 됐다.

**6. 도구가 조용히 다른 걸 준다.** WSL 에서 `nvidia-smi --query-compute-apps` 는
학습 중에도 항상 빈 결과다. 이걸 "GPU 프로세스 없음 = 정지" 신호로 쓴 워치독이
오경보를 냈고, 반대로 호스트 절전으로 CUDA 가 끊겨 **13시간 동안 멈춘 것은
못 잡았다**(프로세스는 살아 있고 로그 마지막 줄도 그대로라 "느림"과 구별 안 됨).
간접 신호 대신 **완료된 epoch 수를 직접 세는** 방식으로 바꿔 해결했다.

## 7. 남은 과제

- **자연 소형 대조군을 늘리는 것.** 지금 14장·121 인스턴스로는 곡선의 방향만
  읽을 수 있고 개별 값은 못 읽는다. 이 프로젝트의 핵심 질문이 걸린 표본이다.
- **타일로 학습한 뒤 SAHI 재평가.** D4 의 결론은 "축소 학습 모델에 얹으면 해롭다"
  까지다. 전제를 맞춘 조건에서 원 논문의 이득이 재현되는지는 안 봤다.
- **모델별 하이퍼파라미터 튜닝 후 YOLO26 재비교.** D3 는 YOLO11 기준 조건에서의
  비교다.
- **cold start 능동학습.** 불확실성이 초반에 무작위로 퇴화하는 문제를 다양성·
