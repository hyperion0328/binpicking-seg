# 기획 — 소형/얇은 산업 부품 정밀 탐지 (SOD, Small Object Detection)

## 0. 왜 이 프로젝트인가

산업 현장에서 나사·너트·볼트처럼 작고 얇은 부품은 표준 객체 탐지 벤치마크(COCO 등)가
가정하는 크기보다 훨씬 작아서, 일반적인 탐지기가 잘 못 잡는다. 이 프로젝트는 "작은
부품을 얼마나 정밀하게 탐지할 수 있는가"를 공개 산업 벤치마크로 실측하고, 어떤
기법이 왜 효과가 있는지 비교한다.

**기획 원칙**: 아래 데이터셋 설명은 전부 각 데이터셋의 공개 문서·논문에서 확인한
내용이지만, 실제 파일을 열어보기 전까지는 "계획"이지 "사실"이 아니다. D1(착수
직후)에 데이터셋을 실제로 받아 라벨 스키마·클래스 수·bbox 형식(axis-aligned인지
oriented인지)을 직접 확인하는 단계를 계획에 명시적으로 넣는다 — 코드를 짜기 전에
라벨 파일 하나는 반드시 직접 열어본다.

## 1. 목표

작고 얇은 산업 부품(나사·너트·볼트 등)을 실제 산업 벤치마크에서 정밀하게 탐지하는
모델을 만들고, 어떤 기법이 왜 효과가 있는지 실측으로 비교한다.

**스코프 — 탐지 모델과 그 주변까지.** 포즈 추정(6D pose)·그립 계획(grasp planning)·
로봇 시뮬레이션은 여전히 스코프 밖이다 — 다루면 스코프가 로보틱스 프로젝트로
바뀐다. 대신 "탐지 모델을 어떻게 더 잘 만들고, 어떻게 실제로 돌릴 수 있는가"라는
축으로는 넓힌다: (a) 소형 객체 특화 데이터 증강(3.1절), (b) 경량화·배포 공학(3.2절).
둘 다 탐지 모델 자체에 대한 작업이라 로봇/포즈 추정으로 스코프가 새지 않는다.

## 2. 데이터 — 공개 벤치마크 주축

자체 수집이나 순수 합성 데이터가 아니라, 이미 검증된 공개 벤치마크를 주 데이터로
쓴다. 다른 연구와 직접 비교 가능한 신뢰도를 얻기 위해서다.

| 데이터셋 | 규모(문서 기준) | 특징 | 역할 |
|---|---|---|---|
| **MVTec Screws** | 384장, 13종 나사/너트, 4,426 라벨 | oriented bbox(회전된 사각형) — axis-aligned보다 어려움 | 주 벤치마크 |
| **NPU-BOLT** | 자연 환경(현장) 볼트 이미지 | YOLOv5-l 기준 공개 AP(97.38%/91.88%) 있음 | 일반화 검증 — MVTec Screws는 통제된 촬영이라, 실제 현장과 비슷한 환경에서도 되는지 확인 |
| **PCBsmdComponents** | 7,661장, 저항/다이오드/트랜지스터/커패시터 4종 | Roboflow Universe 공개 데이터셋 | 세 번째 도메인(전자부품) — 부품 도메인 일반화 확인 |
| BOP-Industrial (ITODD, XYZ-IBD 등) | 800+ 장면, occlusion 심한 빈피킹 상황 | 실제로는 부품 직경 5~30cm — 전혀 작지 않음(D1에서 확인) | 스코프 밖(포즈 추정 확장 시 후보로만 기록) |

### 2.1 D1 실측 결과 — 계획을 뒤집은 발견 (실제 진행일 기준)

계획대로 세 데이터셋(MVTec Screws, NPU-BOLT, PCBsmdComponents)을 전부 받아
라벨을 직접 열어 실측했다.

**확인된 사실 (계획과 일치)**
- MVTec Screws: 384장, 4,427건 라벨(문서 4,426건과 1건 차이), bbox는 정확히
  `(row, col, width, height, phi)` 5파라미터 회전 박스. 클래스는 `type_001`~`type_013`
  로 익명화돼 있어 실제 나사 종류 이름은 라벨에 없음. 이미지 크기 1920×1440 고정.
- NPU-BOLT: 337장, 1,275건 라벨(문서와 일치), 클래스는 `bolt head`/`bolt nut`/
  `bolt side`/`blur bolt` 4종(축정렬 사각형). 이미지 크기가 262×230~4896×3672로
  편차가 큼 — 자연 환경 촬영이라는 문서 설명과 일치.
- PCBsmdComponents: 7,661장, 28,536건 라벨(Resistor 10,467·Diode 8,543·
  Condensator 8,198·Transistor 1,328), Roboflow 표준 export 시 1280×720으로
  통일 리사이즈됨.

**계획을 뒤집은 발견 — 셋 다 "소형 객체" 벤치마크가 아니다.** COCO 기준
(면적 32×32px 미만 = small)으로 실측하면:

| | MVTec Screws | NPU-BOLT | PCBsmdComponents |
|---|---|---|---|
| COCO small(<32×32px) 비율 | 0% | **9.5%**(121/1,275) | 0.2%(57/28,536) |
| 객체 한 변 중앙값(√area) | 231px | 123px | 82.5px |

물리적으로 작은 부품(나사·저항)이라도, **클로즈업으로 촬영된 데이터셋은 이미지
안에서 크게 나온다** — "물리적 크기"와 "이미지 안 픽셀 크기"는 다른 축이고, 촬영
거리(클로즈업 vs 넓은 화각)가 후자를 결정한다. 셋 중 NPU-BOLT만 자연 환경에서
다양한 거리로 찍혀 그나마 유의미한 small 비율을 갖는다.

**그 NPU-BOLT의 9.5%도 충분하지 않다.** 121개 small 인스턴스가 337장 중 **단
14장에만 몰려 있고**, 표준 70/15/15 분할을 적용하면 val·test에 각각 18개 안팎만
남는다 — mAP 하나를 신뢰성 있게 계산하기엔 너무 적고, 클래스별로 쪼개면(예:
`bolt side` 11개) 사실상 지표가 무의미해진다. 운이 나쁘면 특정 분할에 small
인스턴스가 0개가 될 위험도 있다.

### 2.2 방법론 수정 — 다운스케일링을 주 실험 축으로

위 발견에 따라, "실제로 작게 찍힌 데이터를 모은다"는 원래 접근 대신 **의도적
다운스케일링을 주 실험 방법론으로 쓴다**: 세 데이터셋 전체(34,238건 라벨)를 원본
해상도에서 단계적으로 축소해, "객체가 몇 픽셀부터 성능이 무너지는가"를 통제된
곡선으로 측정한다. 물체·질감·배경·클래스 구성을 그대로 두고 픽셀 크기만 바꿀 수
있어 표본 크기 문제도 해결된다.

**한계 — 반드시 실측으로 검증할 것.** 다운스케일된 이미지는 고해상도 원본을
소프트웨어로 축소한 것이라 안티앨리어싱 효과로 오히려 더 깨끗하다. 반면 실제로
카메라에서 멀어서 작게 찍힌 물체는 그 거리에서의 진짜 센서 노이즈·모션 블러가
있다 — **"다운스케일한 깨끗한 소형"과 "실제로 작게 찍힌 소형"은 저수준 통계가
다르다.** 이건 별개 프로젝트(OSV, 작업 순서 검증)에서 "합성 렌더(깨끗함) vs 실제
영상(카메라 노이즈)" 격차 때문에 도메인 랜덤화를 다 해도 실제 영상 성능이 안 올랐던
것과 구조적으로 같은 함정이다.

그래서 평가는 두 숫자를 항상 같이 보고한다:
1. **다운스케일 곡선 기준 AP** — "이 모델이 작은 물체에 얼마나 강한가"의 낙관적
   상한으로 취급
2. **NPU-BOLT 자연 발생 small 서브셋(121개, 14장) 기준 AP(또는 정성적 확인)** —
   표본은 작아 정량 지표로 못 쓰지만, 다운스케일 곡선이 예측한 성능과 실제 소형
   인스턴스 성능이 얼마나 벌어지는지 눈으로 확인하는 대조군. 두 숫자의 격차 자체가
   "다운스케일링만으로는 못 메우는 부분이 얼마나 되는가"라는 이 프로젝트의 결론
   중 하나가 된다.

## 3. 모델·기법 후보

| 후보 | 왜 넣는가 |
|---|---|
| YOLO11n/s (baseline) | 표준 기준선 |
| YOLO26 (STAL) | 소형 객체 라벨 할당에 특화된 기능(Small Target Assignment) — 이 프로젝트의 핵심 질문에 정면으로 맞는 후보 |
| SAHI (타일링 추론) | 재학습 없이 기존 탐지기 위에 얹어 소형 객체 AP를 6~14%p 올린다고 보고된 기법(Akyon et al., 2022) — 가장 싸게 시도해볼 수 있는 개선 |
| SOD-YOLO 계열(소형 객체 특화 아키텍처) | 위 기법들 대비 "아키텍처를 바꾸는 게 얼마나 더 이득인가"를 보는 비교군 |
| Copy-paste 증강 (3.1절) | 학습 데이터 자체를 소형 객체에 유리하게 재구성하는 축 — 위 셋과 독립적으로 조합 가능 |
| ONNX 변환 + INT8 양자화 (3.2절) | 정확도 개선이 아니라 "그 정확도를 실제로 얼마나 빠르게/가볍게 낼 수 있는가"를 보는 축 |
| Weighted Boxes Fusion (3.3절) | 여러 모델을 새로 학습하는 게 아니라 이미 학습된 모델들의 예측을 기하학적으로 병합하는 알고리즘 — 모델 학습과는 다른 종류의 작업 |
| 능동 학습(Active Learning) 시뮬레이션 (3.4절) | 라벨을 어떻게 고르는가에 대한 데이터 선택 알고리즘 — 탐지 모델 자체가 아니라 학습 파이프라인 설계에 대한 축 |
| 설명 가능성(Grad-CAM/Eigen-CAM) (3.5절) | 왜 작은 객체를 놓치는지 시각적 근거를 만드는 진단 축 — 다른 프로젝트(OSV)의 혼동행렬 진단과 같은 성격 |

### 3.1 소형 객체 특화 데이터 증강 — copy-paste

**방법.** 새로 3D 렌더링을 하지 않는다. 대신 이미 가진 실제 이미지에서 라벨된
객체를 잘라내(crop), 다른 이미지 위에 무작위 위치·작은 스케일·회전으로 여러 번
붙여넣는 방식(copy-paste augmentation)을 쓴다. Kisantal et al.(2019)이 이 방식으로
MS COCO 소형 객체 탐지에서 상대 성능 +9.7%(인스턴스 분할)/+7.1%(탐지)를 보고했고,
Ghiasi et al.(CVPR 2021)은 더 일반적인 형태로 이 기법이 강력한 증강법임을 확인했다.

**왜 3D 렌더링(BlenderProc 등)이 아니라 copy-paste인가.** 2.2절에서 이미 짚은
"다운스케일한 깨끗한 이미지 vs 실제 센서 노이즈가 있는 소형 객체"의 격차는, 3D
렌더링을 쓰면 한 번 더(렌더-실사 격차까지 겹쳐서) 발생한다 — 이건 별개 프로젝트
(OSV)에서 합성 렌더링이 실제 영상 성능을 못 올렸던 바로 그 원인이다. Copy-paste는
**실제 카메라가 찍은 진짜 픽셀**(노이즈·블러 포함)을 그대로 재사용하고 배치만
바꾸므로, 렌더링 단계에서 새로 생기는 도메인 갭이 없다 — 지금 스코프에서 가장
안전한 증강 경로다.

**절차**: (1) 세 데이터셋에서 라벨된 객체를 크롭 (2) 배경 이미지 위에 무작위
개수·위치·회전·스케일(작은 쪽에 가중치)로 합성 (3) 기존 객체와 안 겹치게 배치
(Kisantal et al. 방식) (4) 증강 전/후로 baseline을 다시 학습해 다운스케일 곡선이
얼마나 개선되는지, 그리고 NPU-BOLT 자연 소형 서브셋 대비 격차가 줄어드는지 확인.

### 3.2 경량화·배포 공학

**방법.** 가장 성능이 좋았던 조합을 ONNX로 변환하고 INT8 post-training
양자화를 적용해, 정확도·모델 크기·추론 속도의 트레이드오프를 실측한다. 참고할
선행 사례: YOLO11n을 Raspberry Pi 5에서 FP32→INT8로 양자화하면 12.7 FPS →
16.1 FPS(약 27% 향상)로 보고된 바 있다.

**절차**: (1) D2~D5에서 가장 성능 좋았던 조합을 ONNX로 export (2) INT8 양자화
적용(대표 데이터 일부로 calibration) (3) 원본(FP32) vs 양자화(INT8)로 mAP·모델
크기(MB)·추론 속도(FPS)를 이 머신의 CPU/GPU에서 비교 (4) 정확도 손실이 몇 %p일
때 속도·크기 이득이 몇 배인지 표로 정리.

### 3.3 Weighted Boxes Fusion — 모델 앙상블

**방법.** D2~D6에서 나온 여러 모델(YOLO11n, YOLO26, SAHI 적용 결과 등)의 예측
박스를 단순 평균이 아니라, 박스끼리 겹침을 보며 신뢰도 가중 평균으로 점진적으로
병합하는 알고리즘(Solovyev et al., 2021, WBF)을 적용한다. NMS처럼 박스를 버리는
게 아니라, 겹치는 박스들의 좌표·신뢰도를 합쳐 새 박스를 만드는 방식이라 앙상블
시 정보 손실이 적다고 보고돼 있다(Open Images·COCO 챌린지 상위권 방법).

**왜 넣는가.** 지금까지의 모든 축(D2~D6)은 "모델 하나를 어떻게 더 잘 학습·
변환하는가"였다. WBF는 다르다 — **이미 만든 모델들을 새로 학습하지 않고
기하학적으로 조합**하는, 성격이 다른 알고리즘 작업이다. 참고 구현:
ZFTurbo/Weighted-Boxes-Fusion.

**절차**: (1) D2~D6에서 가장 좋았던 서로 다른 모델 2~3개 예측을 각 val 이미지에
대해 수집 (2) WBF로 병합 (3) 단일 최고 모델 대비, 그리고 단순 NMS 앙상블 대비
mAP·소형 객체 AP 비교 (4) 추론 속도 비용(모델 여러 개를 다 돌려야 하므로)까지
같이 보고.

### 3.4 능동 학습(Active Learning) 시뮬레이션

**방법.** 이미 라벨이 다 있는 데이터를 "처음부터 조금만 있었다"고 가정하고
시뮬레이션한다: 적은 수의 라벨된 샘플로 시작해, 남은 미라벨(이라고 가정한) 샘플
중 모델이 가장 불확실해하는 것부터 골라 라벨을 "공개"(오라클 — 이미 갖고 있는
정답을 그때 꺼내 씀)하며 점진적으로 학습셋을 늘린다. 무작위로 추가하는 것과
비교해 같은 라벨 수로 얼마나 더 좋은 성능이 나오는지 측정한다. 참고:
Plug and Play Active Learning(PPAL, Chen et al., 2022)이 쓰는 난이도 보정
불확실성 샘플링 + 다양성 샘플링 조합을 단순화해 적용.

**왜 새 라벨링이 필요 없는가.** 실제로 라벨 안 된 데이터를 모으는 게 아니라,
**이미 있는 라벨을 언제 쓸지 순서만 알고리즘으로 정하는 시뮬레이션**이다 —
2.2절 등에서 이미 "새 라벨링은 스코프 밖"이라고 정한 원칙과 안 어긋난다.

**왜 넣는가.** "작은 객체는 라벨링 비용이 특히 크다"(같은 이미지에 인스턴스가
많아 라벨링 시간이 오래 걸림)는 게 소형 객체 탐지 연구에서 자주 언급되는
현실적 문제다. 이 프로젝트가 "탐지 모델을 만드는 것"을 넘어 "실제로 이걸
도입하려면 라벨링 비용을 얼마나 아낄 수 있는가"까지 답하게 해준다.

**절차**: (1) 전체 학습셋의 5~10%로 시작 (2) 불확실성 점수(예: 낮은 confidence
예측이 많은 이미지) 기준으로 매 라운드 일정 비율씩 라벨 "공개"·재학습 (3) 무작위
추가와 비교해 "같은 성능에 도달하는 데 필요한 라벨 수"를 곡선으로 비교.

### 3.5 설명 가능성 — Grad-CAM / Eigen-CAM

**방법.** 학습된 탐지기가 이미지의 어느 영역(픽셀)에 반응해 예측을 냈는지
히트맵으로 시각화한다. Grad-CAM(그래디언트 기반)과 Eigen-CAM(순전파만 사용,
분류 성능과 무관하게 적용 가능)을 YOLO에 적용한 선행 사례(Explaining YOLO,
2022; Grad-CAM vs EigenCAM on YOLOv5 비교 연구)를 참고한다. 구현은
jacobgil/pytorch-grad-cam(탐지 모델 지원) 활용을 우선 검토.

**왜 넣는가.** 지금까지 "작을수록 어렵다"를 AP 숫자로만 보여줬는데, 이 기법으로
"왜 어려운가"를 시각적으로 보여줄 수 있다 — 예를 들어 작은 객체 영역에서
활성화가 약하게 나오는지, 아니면 엉뚱한 배경에 반응하는지가 다른 문제이기
때문이다. OSV의 혼동행렬 진단(`bit_diff_steps`로 어느 스텝이 문제인지 정량적으로
좁힌 것)과 같은 성격의 진단 작업 — 다른 프로젝트지만 "숫자만이 아니라 원인을
설명하는" 방법론적 습관을 여기서도 이어간다.

**절차**: (1) 다운스케일 비율별로 대표 실패/성공 사례를 뽑아 히트맵 생성
(2) 작은 객체 영역의 활성화 강도를 정성적으로(필요하면 정량적으로도) 비교
(3) D7(WBF) 결과와 단일 모델을 비교해 앙상블이 실제로 다른 영역을 보완하는지도
확인.

## 4. 평가

- mAP@0.5, mAP@0.5:0.95 (표준 지표, 다른 논문과 비교하려면 필요)
- **다운스케일 비율별 AP 곡선** (원본 → 1/2 → 1/4 → ... 축소) — "작을수록 얼마나 더
  어려운가"를 정량화하는 게 이 프로젝트의 핵심 질문이므로 전체 mAP만으로는 부족
  (2.2절 참고)
- **NPU-BOLT 자연 발생 small 서브셋(121개) 대비 다운스케일 곡선 예측값의 격차** —
  다운스케일링 방법론 자체의 신뢰도를 보고하는 항목. 이 격차를 안 재고 다운스케일
  결과만 내면 "실제로는 안 통할 걸 통한다고 주장"하는 것과 같다
- 추론 속도(FPS), 모델 크기(MB) — FP32 vs INT8 양자화 전후로 비교(3.2절)
- copy-paste 증강 전/후 다운스케일 곡선 비교(3.1절) — 증강이 "낙관적 상한"과
  "NPU-BOLT 실측 대조군" 사이 격차를 실제로 줄이는지가 핵심 판단 기준

   baseline을 원본·축소 비율별로 학습·벤치마크, AP 곡선 확보

    전부 포함해서 "어떤 기법이 왜, 어느 스케일부터, 얼마나 실사용 가능하게 효과
    있었는지" 근거 제시
