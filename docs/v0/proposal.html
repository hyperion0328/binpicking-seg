01

문제 정의와 목표

수작업 조립 공정에서 순서 누락·뒤바뀜·잘못된 부품 사용은 품질 불량의 주요 원인이다. 사람이 모든 라인을 실시간으로 감시하기는 어렵고, 사후 추적도 번거롭다. 이 프로젝트는 추가 센서 없이 카메라 영상만으로 조립 순서의 정상 여부를 자동 판정하는 것을 목표로 한다.

?무엇을

부품·도구·손을 인식하고, 그 등장·이동·소실을 표준 작업 순서와 대조해 이상(오류) 여부와 발생 시점을 검출한다.

!왜

센서 부착이 어려운 다품종·비정형 조립에서도 동작하고, 하나의 영상 스트림에서 부품 종류·위치·순서를 동시에 파악할 수 있다.

◔제약

단기 개인 프로젝트. 그래서 MVP를 먼저 완성하고 단계적으로 확장하는 것을 대전제로 설계했다.

설계 원칙

무거운 딥러닝을 처음부터 쓰기보다, 문제 구조를 분석해 규칙으로 풀리는 부분과 학습이 꼭 필요한 부분을 분리한다. 완성 가능한 최소 파이프라인을 먼저 세우고, 정확도·유연성은 단계적으로 얹는다.

02

접근 개요

조립 순서 검증을 하나의 학습 모델로 한 번에 푸는 대신, 판정의 성격에 따라 두 계층으로 나눈다. "무엇이 언제 일어났는가(순서)"는 관측만으로 결정되지만, "그 동작이 제대로 수행됐는가(품질)"는 학습이 필요하다. 성격이 다른 두 문제를 한 모델에 밀어넣으면 학습 데이터 비용이 커지고, 오류가 났을 때 원인이 순서인지 수행인지 분리되지 않는다.

11차 · 규칙 기반 (핵심 MVP)

YOLO 탐지 → 트래킹 → 객체 상대 관계 기반 이벤트화 → 상태머신(FSM)으로 순서 검증. 부품의 등장·소실과 조립체 접촉 여부가 시각적으로 명확해, 탐지·트래킹만으로 규칙 기반 이벤트화가 가능한 구조다.

22차 · 학습 기반 (선택 확장)

1차가 "순서는 정상"으로 판정한 구간에 한해, 학습 기반 행동 인식으로 세부 동작의 정확성(예: 나사를 제대로 체결했는지)을 검증한다. 문제를 잘게 잘라 학습 비용을 줄이는 계층적(cascade) 구조.

왜 화면 좌표 ROI를 쓰지 않는가

IndustReal은 머리 착용 장비로 찍은 1인칭 영상이라 카메라가 상시 움직인다. 화면에 고정 ROI를 그려두면 고개를 돌리는 순간 허위 EXIT가 발생한다. 그래서 조립체 자체를 탐지 클래스로 두고 부품과 조립체의 상대 관계로 판정한다 — 카메라가 어떻게 움직여도 두 객체의 관계는 보존된다. IndustReal의 Assembly State Detection 라벨이 이 조립체 클래스를 그대로 제공한다.

05

모델 선정

공개 벤치마크 순위는 일상 사진 기준이라, 너트·와셔처럼 작고 자주 가려지는 부품에서는 순서가 뒤집힐 수 있다. 게다가 탐지 오차는 이벤트 → FSM 판정으로 그대로 전파된다. 문헌 비교로 끝내지 않고 동일 조건 벤치마크로 baseline을 수치로 못 박은 뒤 최종 선택을 확정한다.

◎트래킹 · ByteTrack vs BoT-SORT vs OC-SORT

YOLO는 프레임 단위 탐지만 하므로 시간적 연속성을 모른다. "부품A가 수 초 머물다 사라짐" 같은 이벤트를 만들려면 프레임 간 객체 ID 유지가 필수다. 트래커도 탐지와 같은 방식으로 실측 비교한다 — 1인칭 이동 카메라라 BoT-SORT의 카메라 움직임 보정(CMC)이 유효할 것으로 보지만, 동일 형상 부품이 많아 외형 기반 Re-ID는 오히려 오매칭을 부를 수 있어 끄고 쓴다. 손에 의한 가림에는 OC-SORT의 가림 재보정이 대안이다.

2확장 · 부분순서 DAG

IndustReal은 서브골(subgoal) 기반으로 여러 유효 순서를 허용한다. 상태를 "지금까지 완료된 스텝의 집합"으로 두고, 새 이벤트의 선행조건이 완료 집합에 포함되는지만 확인 — 위상 정렬 유효성 검사와 동일하다.

절충안

스텝을 5~6개로 단순화하고 "일부만 부분순서, 나머지는 고정 순서"로 설계해 구현 부담을 줄인다.

오류 기준 재사용

IndustReal에 이미 정의된 38종 실행 오류(예: 잘못된 종류의 너트 사용)를 그대로 "이상 판정 기준"으로 사용한다.

시퀀스 비교

순서 오류는 편집거리(Levenshtein), 타이밍·속도 변동은 DTW(Dynamic Time Warping)로 정렬 비교한다.

목표 정확도 (잠정)

held-out 검증셋 기준 정상/이상 이진 판정 정확도 ≥ 85%, 이상 발생 시점 오차 ±1~2프레임 이내를 잠정 목표로 둔다. 05장 탐지 벤치마크가 확정되기 전까지는 가늠치이며, 실측 후 조정한다.

08

2차 검증 — 계층적(cascade) 구조

↑문제 축소

2차 모델을 처음부터 전체 영상에 돌리면 "행동을 찾는" 어려운 문제가 된다. 1차가 이벤트 구간을 먼저 잘라주면, 2차는 "이 짧은 클립이 스텝 X를 올바르게 수행했는가"라는 축소된 분류 문제가 된다.

↓범위 한정

기간이 짧으면 2차 검증 대상 스텝을 1~2개로 한정한다. 정확도를 높이려 무거운 모델을 처음부터 쓰지 않고, 가벼운 모델로 문제를 축소한 뒤 무거운 모델을 투입하는 설계.

10

설계 결정과 근거

선택마다 무엇을 택했고 왜 택했는지를 남기고, 그 아래에 결정들을 관통하는 판단 기준을 정리했다. "왜 이 방법인가"를 설명할 수 있는 것이 이 프로젝트의 핵심 역량이다. 기각한 후보의 상세 비교는 각 장(04 · 05 · 07)에 있다.

결정선택 · 근거
D1 탐지 모델 YOLO (1-stage) — 2-stage(Faster R-CNN)가 정확도에서 유리할 수 있으나, 순서 검증은 다수 프레임을 연속 처리하는 문제라 프레임당 속도가 전체 파이프라인을 좌우한다. 커스텀 파인튜닝도 쉽다.
D1-1 YOLO 버전
D1의 하위 결정		 YOLO11(기준선) + YOLO26(STAL) — YOLO26의 STAL은 너트·와셔·핀 같은 소형 부품 탐지에 특화. YOLO11은 자료가 많아 안정적 기준선. 후보 비교는 05장 참조.
D2 탐지와 트래킹 분리 탐지(YOLO) + 트래킹(ByteTrack) 2단 — 프레임별 탐지 결과만으로는 시간적 연속성을 알 수 없다. "부품A가 수 초 머물다 사라짐" 같은 지속성 기반 이벤트를 만들려면 객체 ID 유지가 필수다.
D3 규칙 기반(FSM) 우선 이벤트 시퀀스 + 상태머신(FSM) — 부품의 등장·소실과 조립체 접촉 여부가 시각적으로 명확해, 학습 기반 행동인식 없이도 탐지+트래킹만으로 규칙 기반 이벤트화가 가능한 구조다.
D3-1 이벤트 기준을 객체 상대 관계로
D3의 하위 결정		 부품–조립체 중첩(IoA) — 화면 좌표에 ROI를 그리는 통상적 방식은 고정 카메라를 전제한다. IndustReal은 1인칭 이동 카메라라 그 전제가 성립하지 않아, 카메라 움직임과 무관한 객체 간 상대 관계로 기준을 바꿨다. 고정 앵글을 가정하는 대신 가정 자체가 필요 없는 기준을 택한 것이다.
D4 사후(오프라인) 판정 우선 사후 판정, 실시간은 확장 과제 — 전체 맥락으로 판단해 노이즈에 강하고, DTW·편집거리로 정량 지표 산출이 쉬워 재현성 있는 평가를 확보한다. 실시간과의 비교는 07장 참조.
D5 1차+2차 계층(cascade) 구조 1차 규칙 계층 + 2차 학습 계층 — 1차가 이벤트 구간을 잘라주면 2차는 "짧은 클립 분류"라는 축소된 문제가 되어 학습 데이터·계산 비용이 준다.
D6 IndustReal 데이터셋 IndustReal — "절차 스텝 인식 + 실행 오류 라벨"이 문제 정의와 정확히 일치. 3D 모델 공개 + Apache 2.0으로 접근성도 좋다. 후보 비교는 04장 참조.
D7 합성 데이터 병행 IndustReal 실제 + BlenderProc 합성 — 실제 데이터는 정상 수행 위주라 합성으로 이상 케이스를 통제 생성한다. 동일 3D 모델을 재사용해 도메인 갭도 줄인다.

판단 기준

개별 결정을 관통하는 기준은 넷이다. 어떤 선택지가 유명한가가 아니라, 이 문제의 구조에 무엇이 맞는가로 판단했다.

① 속도는 파이프라인 전체 처리량으로

단일 프레임 성능이 아니라 다수 프레임을 연속 처리하는 구조를 기준으로 속도–정확도를 판단했다. D1

② 규칙과 학습을 먼저 갈랐다

딥러닝을 기본값으로 두지 않고, 문제 구조를 분석해 규칙으로 풀리는 부분과 학습이 꼭 필요한 부분을 나눴다. D3 · D5

③ 유명세가 아니라 데이터 특성으로

소형 부품 탐지, 절차 스텝 라벨처럼 이 문제에만 해당하는 조건을 충족하는지로 모델과 데이터셋을 골랐다. D1-1 · D6

④ 측정 가능성을 실용성보다 앞에

즉각 대응보다 재현 가능한 정량 평가를 먼저 확보했다. 지표가 서야 이후 개선의 근거가 생기기 때문이다. D4 · D7

본 문서는 기획(설계) 단계 산출물이며, 지표·구현 세부는 이후 실험을 통해 확정·보강된다.

11

확장 설계 설계만 · 미구현

이 장의 범위

아래 두 설계는 검토·설계까지만 진행했고, 이번 스코프에서는 구현하지 않는다.

정확도를 더 올릴 여지는 남아 있다. 두 설계는 "추가 학습 데이터를 무엇으로 채울 것인가"라는 같은 문제에 대한 서로 다른 답이고, 미룬 이유도 각각 다르다 — E1은 오버피팅 위험 때문에, E2는 05장 벤치마크로 baseline이 확정된 뒤라야 의미가 있기 때문이다.

① 재검토 표본은 정의상 "애매했던 경계 사례"라는 편향된 소수 표본 — 단기 프로젝트 특성상 개수도 적어, 그대로 파인튜닝하면 일반적인 탐지력이 아니라 그 몇 장의 특정 프레임을 암기하는 방향으로 갈 수 있다.
② IndustReal은 27명 참가자로 한정 — 재검토 표본이 일부 참가자에게 몰리면 "소형 부품 탐지"가 아니라 그 참가자들의 손 모양·작업 습관에 과적합될 위험이 있다.
③ 같은 사람이 계속 라벨링하면, 모델이 정답이 아니라 그 리뷰어의 판단 패턴(과 실수)을 학습하고, 다음 라운드의 "애매한 케이스" 선별에도 그 편향이 반영되는 순환이 생길 수 있다.

실제로 추가 학습을 구현한다면 필요한 안전장치 (참고용, 미구현) 이 루프와 무관하게 손대지 않는 고정 held-out 검증셋을 유지해 재학습 전후 성능을 항상 비교 · 재학습 배치에 재검토 케이스만이 아니라 랜덤 정상 샘플을 섞어 분포 편향 완화 · 재학습 데이터도 영상/참가자 단위 split(04장) 원칙을 동일하게 적용 · 재학습 빈도를 제한(예: 최소 N건 누적 시에만)해 매 건마다 반응하지 않음
E2 미구현

혼동행렬 기반 합성 하드 네거티브

"어떤 클래스가 약한가"를 사람 판단이 아니라 held-out 검증셋의 지표로만 결정하고, 그 약점을 합성 데이터 생성 파라미터에 되먹인다. E1이 사람을 루프에 넣는 설계라면, E2는 사람을 루프에서 빼는 설계다.

12

한계

11장의 확장 설계가 "왜 아직 안 했는가"라면, 이 장은 지금 스코프가 애초에 다루지 않는 범위를 정리한 것이다. 한계를 명시하는 것 자체가 설계 완성도의 일부다.

1조립체 탐지가 단일 실패점

실측(D1) 결과 부품 단위 bbox는 라벨에 없어, 이벤트 판정은 부품–조립체 상대 관계가 아니라 조립체 상태(24종) 분류 그 자체로 바뀌었다. 조립체 탐지·분류가 흔들리면(손·몸에 가려지거나 상태 자체가 애매한 구간) 그 프레임의 판정이 통째로 불가능해진다는 결론은 그대로다 — 오히려 실측(D3~D5)으로 구체적인 취약 구간까지 확인됐다(아래 참고).

2대표 순서 1개만 정답 (MVP) — 실측 확인

IndustReal이 허용하는 48개 유효 순서 중 MVP는 대표 1개만 고정 순서로 처리한다. val 9개 영상 실측(2026-07-30)에서 이진 판정 정확도 44.4%(목표 85%)로 크게 미달했는데, 정상 영상 5개 중 재작업(이미 끝낸 서브골을 다시 여는 유효 경로) 1건이 이 한계로 직접 오탐됐다 — 예상이 아니라 실측으로 확인된 한계다. 나머지 4건은 별도 원인(중간 상태 분류 신뢰도)이라 이 한계만으로 정확도 저하 전부를 설명하진 못한다. 완화책은 06장 부분순서 DAG 확장.

3사후(오프라인) 판정

이상 발생 즉시 개입이 필요한 안전사고성 오류에는 대응하지 못한다. 작업 종료 후 확인·기록 용도로 한정된다.

4합성-실제 도메인 갭 잔존

IndustReal의 실제 3D 모델을 재사용해도, 조명·질감·occlusion 패턴 차이로 sim-to-real 갭이 완전히 사라지진 않는다.

5지속적 성능 개선 루프 미구현

배포 이후 재검토·추가 학습 경로(11장)는 설계만 돼 있고 구현하지 않아, 최초 학습 시점 이후 성능은 자동으로 개선되지 않는다.

6일부 상태 분류가 구조적으로 불안정 — 실측 확인

44.4% 정확도의 더 큰 원인(정상 오탐 5건 중 4건)은 재작업이 아니라 특정 상태 2종(중간 진행 단계) 자체의 분류 신뢰도였다. 벤치마크(D2)의 정적 mAP는 나쁘지 않았는데 실제 영상 시계열에서는 confidence 0.3~0.6대로 불안정했다 — 정적 벤치마크만으로는 실전 신뢰도를 보장할 수 없다는 방법론적 한계이기도 하다.
