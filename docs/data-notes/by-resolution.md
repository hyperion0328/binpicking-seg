# by_resolution — 해상도별로 묶은 선택 데이터셋

`../selected/` 의 네 세트를 **이미지 해상도별로 분리**한 것. 각 그룹은 그 해상도의
이미지만 담고, `annotations.coco.json` 에 해당 이미지의 주석만 들어 있다.

- 이미지는 **하드링크**라 디스크를 추가로 쓰지 않는다(`du` 127M 은 원본과 공유하는 양).
  원본 `../selected/` 를 지우면 링크가 실제 데이터를 붙들고 있으므로 파일은 남는다.
- 원래 split(train/valid/test)은 각 이미지 레코드의 `"split"` 필드에 보존했다.
  그룹별로 `image_id`/`annotation id` 를 1부터 다시 매겼다.
- `categories` 는 원본 그대로 두었다 — **`id=0` 자리표시자(인스턴스 0개)가 들어 있으니
  학습 변환 시 반드시 뺄 것**(PCBsmd `smd` 와 같은 함정).

객체 크기는 외접 축정렬 박스의 `sqrt(area)`. "변대비" = `sqrt(area) / sqrt(W*H)`.

## 그룹별 성격

**`rf-arg-fixings3/640x480` — 자연 소형 대조군 후보.** 사진을 직접 열어 확인한 결과
**UR 로봇 팔이 설치된 작업 셀을 통째로 찍은 원거리 장면**이고, 흰 작업대 위 나사·볼트가
화면에서 몇 픽셀에 불과하다. 객체 중앙값 11.6px / COCO small 98.3% 로 WDSD(10.8px/98%)와
같은 수준인데 **도메인이 로봇 작업 셀이라 빈피킹 응용과 맞는다.**
`docs/results.md` 7절이 최우선 과제로 남긴 "자연 소형 대조군 확대"에 그대로 쓸 수 있다.
현재 NPU-BOLT 대조군(14장/121개)의 **4배 규모**.

> 이 그룹을 학습에 섞으면 "다운스케일이 진짜 소형을 대신하는가"를 잴 대상이 사라진다.
> **held-out 으로 완전히 빼둘 것.**

**`rf-arg-fixings3/4080x3072` — 스마트폰 근접 촬영**(`PXL_*`). 작업대 위 부품을 가까이서
찍었다. 같은 데이터셋 안에서 640×480 과 정반대 극단이라, **한 세트 안에 촬영 거리
스펙트럼이 들어 있다.**

**`rf-arg-fixings3/3072x4080` — 주석 0개.** 세로 사진 6장. 변환 시 제외할 것.

**`rf-arg-fixings3/640x360` — 인스턴스 12장에 16개뿐.** 통계적으로 의미 없다.

**나머지 세 세트는 해상도가 하나뿐이다.** Roboflow 내보내기가 512×512(stretch) 또는
640×640 으로 균일 리사이즈해서 **원본 촬영 거리 정보가 지워졌다.**
특히 `rf-screw-nut-bolt` 의 COCO small 60.1% 는 **512로 줄인 결과이지 원거리 촬영이 아니다** —
이 값을 "이 데이터셋에는 소형 객체가 많다"의 근거로 인용하면 D1 에서 지적된 것과 같은 오독이 된다.
