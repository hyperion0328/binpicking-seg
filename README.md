# 작고 얇은 부품 찾기 AI — 2차

빈피킹(로봇이 상자에서 부품을 집는 작업)용으로, 작고 얇은 체결부품(나사·볼트·너트·와셔)을
공개 데이터에서 **인스턴스 분할**하는 프로젝트. 겹쳐 쌓인 더미에서 개체 경계를 픽셀 단위로
갈라내는 것이 목표이고, **SAM** 을 마스크 보충과 검증 대상으로 함께 쓴다.

**이 저장소의 산출물은 코드가 아니라 "왜 이 선택인가"에 대한 답이다.**

---

## 결론 한 줄

**줄여서 만든 소형 객체 성능 곡선은 진짜 소형 객체 성능의 낙관적 상한이고, 그 격차는
헤드 구조로도 모델 크기로도 메워지지 않았다.**

| | 점수 |
|---|---|
| 근접 촬영 (줄여서 작아진 물체 포함) | box **0.814** / mask **0.613** |
| **원거리 촬영** (원래 작게 찍힌 물체) | box **0.139 ~ 0.162** |

같은 모델·같은 설정에서 **약 6배** 차이. 무너지는 문턱은 **12픽셀** 부근이다.

## 실측 요약

**데이터** — 공개 4종 1,812장 / 33,923개 / 전부 CC BY 4.0. 3라운드에 걸쳐 20종 이상 검토.
원거리 데이터가 없는 것은 검색 실패가 아니라 구조적 사실이다 —
*부품이 주인공이면 반드시 근접 촬영이고, 부품이 작게 찍혔으면 반드시 다른 것이 주인공이다.*

**대조군** — `rf-arg-fixings3` 640×480 그룹 24장. 물체 중앙값 **11.6px**, 98.3%가 32px 미만.
**학습에 한 번도 넣지 않았다.**

**학습 26회** — 주 곡선 6(n·s × 640/320/160) · P2 2×2 6 · 화질 축 3 · 결합 3 · 크기 1 · 계열 1 ·
기준선 1 · P2 단독 640 1 · **epoch 맞춤 재확인 3**. GPU 20.3시간.

| 축 | 결과 |
|---|---|
| 축소 곡선 | mask 0.613(640) → 0.320(320) → 0.122(160) |
| 대조군 | box **0.139~0.162**. test의 1/6 |
| 크기별 검출률 | 24px+ **91%** → 8px 미만 **12%** |
| 마스크 vs 박스 | mask/box 비 0.75(640) → 0.30(160). **마스크가 먼저 무너진다** |
| P2 헤드 | **쓰지 않는다.** 줄인 test 는 +17.9%(160)/+4.0%(320)인데 **대조군은 −13.1%(320)/−15.1%(640)** |
| 모델 크기 | n → s 는 오르고 **s → m 은 개선 없음** |
| 화질 열화 증강 | 낯선 도메인 0.553 → **0.795**(과적합 억제) |
| SAM | 정밀도 0.97로 검증 후 학습용에만 2,536개 채움(97.3% 통과) |

## 판단이 뒤집힌 기록

이 프로젝트가 남기려는 것에 가장 가깝다. 근거는 전부 `docs/experiments.md`.

1. **출처를 고정하지 않은 크기 곡선은 읽지 않는다** — SAM IoU가 크기와 무관해 보였는데 출처가 섞여 있었다
2. **일치도 하나로 원인을 지목하지 않는다** — 낮은 IoU는 SAM이 아니라 거친 정답 탓이었다(정밀도 0.97 / 재현율 0.70)
3. **기대한 부수효과는 재보고 적는다** — 소형 사진 오버샘플링이 쏠림을 완화하지 않았다(82.9% → 84.8%)
4. **전제가 틀려도 그 전제에서 나온 처방은 따로 재본다** — "줄인 사진이 깨끗하다"는 틀렸지만 열화 증강은 통했다
5. **조기 종료 epoch가 다른 런끼리 비교하지 않는다** — 안 맞췄으면 이득을 3배 부풀릴 뻔했다
6. **대리 지표에서 이긴 처방은 실물에서 다시 재기 전에 채택하지 않는다** — P2 헤드는 줄인 test 에서 이기고 대조군에서 졌다. 격차는 점수 수준만이 아니라 **무엇을 고를지**도 바꾼다

도구가 조용히 틀린 경우 셋 — 발산 감지기가 없는 파일을 보고 통과, 노이즈 추정기가 나사산
질감을 노이즈로 셈, `albumentations` 미설치로 12회 학습에 화질 증강이 한 번도 안 걸림.

## 실행

```bash
scripts/01_build_dataset.py   # 전처리 -> data/build/
scripts/02_sam_validate.py    # SAM 크기별·출처별 IoU
scripts/03_sam_diag.py        # IoU 저하 원인 분리(정밀도·재현율)
scripts/04_sam_washer.py      # 와셔 구멍 처리와 SAM 모델 비교
scripts/05_sam_fill.py        # 관문 통과분만 채우기
scripts/06_to_yolo.py         # COCO -> YOLO-seg (이미지 복제 없음)
scripts/07_train.py           # 학습 (--cfg P2 / --mask-ratio / --degrade / --flatten)
scripts/08_eval.py            # 평가 (출처별 분리, 통일 잣대)
scripts/09_imgstats.py        # 사진 전체 화질 통계
scripts/10_quality_gap.py     # 물체 크기를 맞춘 화질 비교
scripts/11_visualize.py       # 정답/예측 겹쳐 보기 · 놓친 것 · 조건 비교
```

`~/venvs/sod` (torch 2.6.0+cu124 / ultralytics 8.4.113 / RTX 4070 12GB).
seed 0 · deterministic · batch 16 고정. `data/`·`runs/`·`outputs/`·`*.pt` 는 추적하지 않는다.

분할용 P2 설정과 그것을 쓰기 위한 검증기 보정은 `configs/yolo11s-seg-p2.yaml`,
`sodseg/p2_seg.py` 에 있다 — 설치본의 P2 설정은 전부 탐지 전용이다.
